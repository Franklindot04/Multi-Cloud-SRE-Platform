# Scripts

Small helper scripts used by the Makefile, CI and local development. Shell scripts are linted with `scripts/shellcheck.sh`, which runs `shellcheck -S style` (the strictest level, so info and style findings fail) at the version CI installs (0.11.0); `make argocd-check` and `make apps-lint` both use it. Scripts must be idempotent, use `set -euo pipefail`, print usage with `-h`, and avoid embedding credentials.

- `teardown-prep.sh --context CONTEXT [--region R] [--cluster-name N] [--dry-run]`: prepares a cluster for `terraform destroy` (removes the Argo CD cluster Secret labels, then deletes the CloudNativePG `Database` objects and `Cluster`, the `RabbitmqCluster` and the claims, waits for the metrics foundation's pods and deletes its claims if its namespace exists, and checks volumes, load balancers and security groups; 14 steps, listed in the script header and the runbook). When an operator is already gone, it removes the one operator finalizer from a stuck `Database` or `RabbitmqCluster` and says so; any other finalizer is left alone and the script stops. It clears no Prometheus Operator finalizer: the operator sets none in this configuration (see [ADR-0020](../docs/adr/0020-metrics-stack.md)). See the [data layer runbook](../docs/runbooks/data-layer.md#teardown) and its note on a namespace stuck in `Terminating`. Tested against a fake `kubectl` and `aws` in `scripts/tests/fakes` by `scripts/test-scripts.sh`.
- `teardown-argocd.sh --context CONTEXT [--timeout S] [--dry-run]`: runs after `teardown-prep.sh` and before `terraform destroy`. Refuses to start while a persistent volume or a claim in the `data` namespace is left, deletes the `data`, `shop` and `observability` namespaces and the `platform-data` storage class, deletes `platform-root` and the ApplicationSets, waits for the Applications, runs `helm uninstall argocd` (a missing release is fine) and deletes the `argocd` namespace; 9 steps, listed in the script header. When the application controller is no longer running, it removes the one finalizer `resources-finalizer.argocd.argoproj.io` from Applications that are stuck on it and from the AppProjects left, with a guarded patch, and says so; it never forces and touches no other finalizer. See the [Argo CD runbook](../docs/runbooks/argocd.md#teardown). Tested against a fake `kubectl` and `helm` by `scripts/test-scripts.sh`; not yet run against a real cluster.
- `chart-contract-check.py` and `python-with-yaml.sh`: contract checks run by `data-manifests-check.sh`, `deploy-check.sh`, `observability-check.sh` and `argocd-check.sh` (no hook-only chart, no Helm-hook Job that creates Secrets, the PostgreSQL PreSync gate, the sync-wave order of the data and observability ApplicationSets; for the metrics foundation also restricted Pod Security, no persistent storage, Grafana's admin Secret, digest pinning, the Prometheus Operator CRDs and the fit with the AppProject).
- `logql-check.py LOKI_URL DASHBOARD_DIR`: runs every Loki query of the Grafana dashboards against a running Loki, with sample lines in the shapes the services log, and checks what comes back; started by `observability-check.sh`.
- `trace-check.py TEMPO_URL COLLECTOR_URL`: sends one trace to a collector and looks for it in Tempo; started by `observability-check.sh` with containers made from the rendered configuration.
- `observability-check.sh`: offline checks of the metrics and logging stack under `platform/observability` (`make observability-check`): chart lint, render and schema checks, the operator's CRDs, vendored chart pinning, the contracts above, and, when Docker is running, the collector, Loki and Alloy configurations validated with their images, the dashboards' LogQL run against a Loki container (`logql-check.py`), and a trace sent to a collector and found in a Tempo container (`trace-check.py`); it also checks the Tempo configuration and the Grafana data sources. Run by `.github/workflows/observability.yml`.
- `verify-image.sh SERVICE|all [DIGEST]`: checks the signature, the SBOM attestation and the build provenance of a published image with cosign, pinned to the images workflow on `main` of this repository and the GitHub OIDC issuer; prints PASS or FAIL per check and per image and exits non-zero on any failure. See [verify an image](../docs/runbooks/service-deployment.md#verify-an-image). Tested against a fake `cosign` in `scripts/tests/fakes`, and run against the real signatures of the published images.
- `check-trivyignore.sh [FILE]`: checks `.trivyignore` before an image scan: every entry needs a `# reason:` line directly above it and an unexpired `exp:YYYY-MM-DD` date. Run by the images workflow and tested by `scripts/test-scripts.sh`.
